셸 환경을 관리하는 도구 중에는 터미널을 열 때마다 백그라운드에서 최신 버전을 확인하거나 자동 업데이트를 실행하는 경우가 많다. 최신 환경을 유지한다는 목적에는 맞지만, 네트워크 상태에 따라 새 창이나 탭을 열 때마다 간헐적인 입력 지연이 생긴다.

Selfishell에서는 셸 시작 경로에서 네트워크 I/O를 완전히 배제하고 상태 확인을 명시적인 명령으로 분리하기로 했다.

## 셸 시작 경로에는 로컬 파일 읽기만 남긴다

터미널을 열었을 때 `.zshrc`가 처리해야 하는 작업은 환경 변수와 함수, alias를 등록하는 것뿐이다. 이 과정에서 원격 서버의 릴리스를 조회하거나 git fetch를 시도하면 오프라인 환경이나 불안정한 네트워크에서 셸이 멈칫거리는 원인이 된다.

Selfishell의 초기화 스크립트는 로컬에 이미 설치된 파일만 `source`하도록 한정했다. 업데이트 확인을 포함해 네트워크를 사용하는 모든 동작은 셸 시작 루프 밖으로 밀어냈다.

## 상태 확인과 진단을 독립된 명령으로 분리한다

자동 확인을 없앤 대신 현재 설치 상태와 환경 이상을 파악할 수 있는 명령을 따로 제공했다.

- `selfishell status`: 현재 활성 버전, 설치된 프로필, 업데이트 가능 여부를 확인한다.
- `selfishell doctor`: 권한, XDG 경로, 심볼릭 링크 상태, 필수 도구 설치 여부를 점검한다.

사용자가 원할 때만 상태를 조회하고 업데이트(`selfishell update`)를 실행하도록 역할을 나누니, 일상적인 터미널 작업에서는 네트워크 지연이 발생하지 않는다.

## 임시 환경에서 셸 시작 시간을 측정해 검증한다

셸 도구는 기능이 추가될수록 점차 무거워지기 쉽다. 이를 방지하기 위해 테스트 과정에서 셸 시작 성능을 지속적으로 측정한다.

사용자의 실제 환경과 섞이지 않도록 임시 `HOME` 디렉터리를 만들고, 프로필별로 셸이 초기화되는 데 걸리는 시간을 측정해 기준치를 넘지 않는지 확인한다. 셸이 켜지는 짧은 순간의 반응성을 유지하는 것은 도구의 부가 기능보다 중요한 기본 품질이기 때문이다.
