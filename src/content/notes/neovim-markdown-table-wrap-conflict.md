Neovim에서 기술 문서나 노트를 작성할 때 긴 문장을 편하게 읽기 위해 `wrap` 옵션을 켜는 경우가 있다. 하지만 마크다운 뷰어 플러그인(`markview.nvim`)을 함께 사용하면서 테이블 렌더링이 깨지는 문제가 발생했다.

## wrap 활성화 시 테이블 렌더링 폴백 문제

`markview.nvim`은 마크다운 테이블의 테두리를 깔끔한 상자 그리기 문자로 렌더링해 준다. 그러나 윈도우에 `wrap` 옵션이 켜져 있으면 이 기능이 강제로 해제되고 일반 파이프(`|`) 문자로 표시됐다.

플러그인 내부 코드를 확인해 보니, soft-wrap이 적용된 버퍼에서는 가상 텍스트 너비와 좌표를 계산할 때 렌더링이 깨지는 문제가 있어 개발자가 wrap 상태에서의 테이블 렌더링을 의도적으로 비활성화해 둔 상태였다.

## 테이블 구조 보존을 위한 wrap 비활성화

두 기능 중 하나를 선택해야 했다.

- 산문 가독성을 위해 `wrap`을 유지하고 테이블의 시각적 렌더링을 포기할 것인가
- 테이블 구조를 깔끔하게 유지하기 위해 `wrap`을 끌 것인가

기술 문서에서는 표의 컬럼 구조와 데이터를 한눈에 파악하는 것이 긴 줄을 접어 보는 것보다 가독성에 더 중요하다고 판단했다. 따라서 마크다운 버퍼에서 `wrap`을 끄고 테이블 렌더링을 보존하기로 결정했다.

## 오버플로우 마커를 통한 긴 줄 시각화

`wrap`을 끄면 화면 너비를 넘어가는 긴 줄이 잘려서 보이지 않는 문제가 생긴다. 이를 보완하기 위해 화면 밖으로 텍스트가 이어져 있음을 알리는 시각적 마커(`listchars`와 `showbreak`)를 설정했다.

화면 끝에 도달한 텍스트 옆에 연장 표시가 나타나므로 사용자가 오른쪽으로 내용이 더 있음을 바로 인지하고 스크롤할 수 있다. 플러그인의 한계를 억지로 패치하기보다, 에디터의 기본 표시 설정을 활용해 절충점을 찾았다.
