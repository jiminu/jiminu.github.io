인공위성 간 충돌 위험 평가(Conjunction Assessment)의 **시간 필터**(Time Filter) 단계에서는 3차원 우주 공간에 분산된 수만 개의 물체 중, 탐색 임계 반경($D_F$) 이내에 진입하는 후보 쌍을 빠르게 색인해야 한다.

동일한 3차원 점 집합 근접 탐색 문제에 대해 **Bucket Hashing**(고정 격자 공간 해싱)과 **kd-tree**(k차원 이진 분할 트리) 두 자료구조를 구현하고, 전처리 시간, 메모리 사용량, 쿼리 속도 간의 정량적 트레이드오프를 측정했다.

![kd-tree와 Bucket Hashing의 탐색 시간 및 벤치마크 비교](/images/three-filter/querytime.png)

## 1. Bucket Hashing: 일정한 격자 분할과 경량 메모리

Bucket Hashing은 3차원 공간을 한 변의 길이가 $D_F$인 균일한 정육면체 셀(Voxel)들로 분할하고, 해시 테이블에 물체들을 매핑하는 방식이다.

- **시간 복잡도**: 생성 $O(N)$, 평균 탐색 $O(1)$, 최악 탐색 $O(N)$
- **동작 원리**: 질의점(Query Point)의 좌표를 해싱하여 해당 점이 속한 셀과 인접한 26개 이웃 셀(총 27개 셀)의 물체들만 후보군으로 검사한다.
- **장점**: 해시 테이블 구조상 전처리 구축 속도가 빠르고(20,800개 기준 16초), 트리 포인터 오버헤드가 없어 메모리를 적게 사용한다(9.6GB).
- **단점**: 우주 공간처럼 물체들이 특정 궤도 평면에 밀집되고 대다수 공간이 비어 있는 환경에서는 27개 셀의 경계 검사 비용이 비효율을 유발한다.

## 2. kd-tree: 계층적 공간 분할과 빠른 질의 수렴

kd-tree는 $k$차원 공간을 매 깊이마다 $X, Y, Z$ 축을 번갈아 가며 중앙값(Median) 기준으로 반씩 분할하는 이진 탐색 트리다.

- **시간 복잡도**: 생성 $O(N \log N)$, 평균 탐색 $O(\log N)$, 최악 탐색 $O(N)$
- **동작 원리**: 루트 노드부터 탐색 반경 $D_F$ 구체(Sphere)와 현재 분할 평면 사이의 거리를 비교하여, 반경에 닿지 않는 서브트리를 조기에 가지치기(Pruning)한다.
- **장점**: 밀집도에 따라 유연하게 분할되므로 불필요한 빈 공간 탐색을 원천 배제한다. 20,800개 All-vs-All 해시 탐색 기준 **Bucket Hashing(1,693초) 대비 약 20% 빠른 1,114초**를 기록했다.
- **단점**: 정렬 및 트리 생성 오버헤드로 전처리 시간(30초)과 메모리(11.0GB)가 다소 높다.

| 구분 (20,800개 All-vs-All) | Preprocessing Time | Memory (GB) | Hash Search Time | Total Query Time |
| :--- | :--- | :--- | :--- | :--- |
| **Bucket Hashing** | **26 s** (우세) | **9.6 GB** (우세) | 1,693 s | 4,338 s |
| **kd-tree** | 40 s | 11.0 GB | **1,114 s** (우세) | **3,620 s** (우세) |

## 3. 샘플링 시간 간격(Δt)과 탐색 반경의 상호작용

궤도 시뮬레이션의 샘플링 간격 $\Delta t$가 증가하면 위치 추정 오차 범위를 보정하기 위해 탐색 반경 $D_F = 2 v_{max} \Delta t + D_{critical}$ 또한 선형적으로 커진다.

![시간 간격 변화에 따른 메모리 및 쿼리 시간 추이](/images/three-filter/timestep-memory.png)

1. **$\Delta t$가 짧을 때 (5s)**: $D_F$가 110km로 매우 좁아져 해시 탐색 시 검사해야 할 후보 쌍 수가 급감하고 쿼리 시간이 빨라진다(Total Query 861초). 반면 타임스텝 수가 많아져 전처리 시간(333초)과 메모리(130GB)가 급증한다.
2. **$\Delta t$가 길 때 (60s)**: 타임스텝 수가 적어 메모리는 11GB로 절약되지만, $D_F$가 1,210km로 커져 검사 후보 쌍이 폭증하고 정밀 Bisection 연산 횟수가 늘어나 쿼리 시간이 3,620초로 증가한다.

## 4. 결론

- **단일 질의 및 대규모 반복 쿼리**: 반복적인 최근접 검색이 지배적인 충돌 예측 파이프라인에서는 쿼리 시간에서 20% 이상의 이점을 갖는 **kd-tree**가 더 유리하다.
- **최적의 운영 파라미터**: 메모리 허용 범위가 충분하다면 $\Delta t = 5\text{s} \sim 10\text{s}$ 구간을 선택하는 것이 전체 쿼리 레이턴시를 최소화하는 최적 균형점이다.
