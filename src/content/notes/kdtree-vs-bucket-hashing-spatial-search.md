Conjunction Assessment의 Time Filter 단계에서는 3D 공간에 분산된 수만 개의 물체 중, 탐색 임계 반경($D_F$) 이내에 진입하는 후보 쌍을 빠르게 색인해야 한다.

동일한 3차원 근접 탐색 문제에 대해 Bucket Hashing과 kd-tree를 구현하고, 전처리 시간, 메모리 사용량, 쿼리 속도를 비교했다.

![kd-tree와 Bucket Hashing의 탐색 시간 및 벤치마크 비교](/images/three-filter/querytime.png)

## 1. Bucket Hashing

3차원 공간을 한 변의 길이가 $D_F$인 균일한 Voxel들로 분할하고 해시 테이블에 매핑하는 방식이다.

- **복잡도**: 생성 $O(N)$, 평균 탐색 $O(1)$, 최악 탐색 $O(N)$
- **동작**: Query Point 좌표를 해싱해 해당 셀과 인접 26개 이웃 셀(총 27개 셀)의 물체들만 후보군으로 검사한다.
- **특징**: 전처리 구축 속도가 빠르고(20,800개 기준 26초), 트리 포인터 오버헤드가 없어 메모리를 적게 쓴다(9.6GB). 다만 물체가 특정 궤도면에 밀집되고 빈 공간이 많은 우주 환경에서는 27개 셀 경계 검사 비용이 증가한다.

## 2. kd-tree

$X, Y, Z$ 축을 번갈아 가며 Median 기준으로 반씩 재귀 분할하는 이진 탐색 트리다.

- **복잡도**: 생성 $O(N \log N)$, 평균 탐색 $O(\log N)$, 최악 탐색 $O(N)$
- **동작**: 탐색 반경 $D_F$ Sphere와 분할 평면 간 거리를 비교해, 반경에 닿지 않는 서브트리를 Pruning한다.
- **특징**: 밀집도에 따라 유연하게 분할되어 빈 공간 탐색을 배제한다. 20,800개 All-vs-All 탐색 기준 **Bucket Hashing(1,693초) 대비 약 20% 빠른 1,114초**를 기록했다. 대신 트리 구성으로 인해 전처리 시간(40초)과 메모리(11.0GB)가 다소 높다.

| 구분 (20,800개 All-vs-All) | Preprocessing Time | Memory (GB) | Hash Search Time | Total Query Time |
| :--- | :--- | :--- | :--- | :--- |
| **Bucket Hashing** | **26 s** (우세) | **9.6 GB** (우세) | 1,693 s | 4,338 s |
| **kd-tree** | 40 s | 11.0 GB | **1,114 s** (우세) | **3,620 s** (우세) |

## 3. 샘플링 시간 간격(Δt)과 탐색 반경의 상호작용

샘플링 간격 $\Delta t$가 증가하면 위치 추정 오차 보정을 위해 탐색 반경 $D_F = 2 v_{max} \Delta t + D_{critical}$ 또한 커진다.

![시간 간격 변화에 따른 메모리 및 쿼리 시간 추이](/images/three-filter/timestep-memory.png)

1. **$\Delta t$가 짧을 때 (5s)**: $D_F$가 110km로 좁아져 후보 쌍 검사 수가 적고 쿼리가 빨라진다(Total Query 861초). 대신 타임스텝 수가 많아 전처리 시간(333초)과 메모리(130GB)가 증가한다.
2. **$\Delta t$가 길 때 (60s)**: 타임스텝 수가 적어 메모리는 11GB로 줄어들지만, $D_F$가 1,210km로 커져 검사 대상 후보 쌍과 Bisection 연산 횟수가 늘어나 쿼리 시간이 3,620초로 증가한다.

반복적인 최근접 검색이 지배적인 파이프라인에서는 쿼리 시간에서 약 20% 우세한 kd-tree가 적합하며, 메모리 여유가 있다면 $\Delta t = 5\text{s} \sim 10\text{s}$ 구간이 전체 지연 시간을 최소화하는 균형점이다.
