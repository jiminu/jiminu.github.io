셸 환경 설치 도구는 `.zshrc`를 수정해야 할 때가 많다. 파일 전체를 복사하거나 심볼릭 링크로 바꾸면 구현은 간단하지만, 사용자가 이미 작성한 alias, function, PATH 설정까지 도구의 관리 대상이 된다.

Selfishell에서는 `.zshrc`를 사용자 소유 파일로 남겨 두고 연결점만 관리하기로 했다.

## 전용 블록 기반 관리 영역 한정

Selfishell이 `.zshrc`에 추가하는 내용은 XDG 경로 아래의 관리 설정을 불러오는 짧은 블록 하나다.

```zsh
# >>> Selfishell initialize >>>
if [[ -r "${XDG_CONFIG_HOME:-$HOME/.config}/selfishell/zsh/zshrc" ]]; then
  source "${XDG_CONFIG_HOME:-$HOME/.config}/selfishell/zsh/zshrc"
fi
# <<< Selfishell initialize <<<
```

실제 기본 설정은 `${XDG_CONFIG_HOME:-$HOME/.config}/selfishell` 아래에 둔다. 사용자의 alias, function, PATH와 export는 표시된 블록 밖에 남는다. 업데이트할 때도 도구가 바꾸는 범위는 이 블록과 자체 XDG 디렉터리뿐이다.

## 파일 형식 및 권한 사전 검사

설치 전에 `.zshrc`가 일반 파일인지 검사한다. 심볼릭 링크거나 다른 종류의 경로라면 대상을 따라가거나 덮어쓰지 않고 중단한다. 어느 파일이 수정될지 확실하지 않은 상태에서 편의를 위해 진행하지 않는 쪽을 택했다.

블록을 추가하거나 교체할 때는 임시 파일에 기존 내용을 복사한 뒤 필요한 구간만 이어 붙인다. `cp -p`로 기존 권한을 보존하고, 완성된 임시 파일을 마지막에 원래 경로로 옮긴다.

## 체크섬 기반 사용자 변경 보호

설치 당시 블록의 체크섬을 상태 파일에 기록한다. 다음 업데이트에서 현재 블록이 그 체크섬과 다르면 사용자가 수정한 것으로 판단한다.

대화형 실행에서는 변경된 블록을 유지할지, 백업한 뒤 새 블록으로 교체할지 선택할 수 있다. 자동 실행에서는 임의로 덮어쓰지 않고 오류를 반환한다. 도구가 만든 영역이라도 설치 이후 사용자가 수정했다면 다시 사용자 데이터로 취급한다.

## 제거 및 원본 복원 검증

테스트에서는 줄 끝이 CRLF이고 마지막 개행이 없는 `.zshrc`를 준비하고 권한을 `0640`으로 설정한다. 설치와 업데이트 후 원래 내용과 권한이 유지되는지 확인하고, `uninstall --restore` 후에는 파일이 처음과 byte 단위로 같은지 검사한다.

재설치했을 때 관리 블록이 중복되지 않는지도 함께 확인한다. 설치뿐 아니라 업데이트와 제거 과정에서도 사용자 파일의 상태를 온전히 보존해야 하기 때문이다.

이 구조를 만들면서 파일을 두 종류로 나누게 됐다. 도구 전용 디렉터리처럼 전체를 관리할 수 있는 파일과 `.zshrc`처럼 연결점만 관리해야 하는 파일이다. 설정 관리 기능을 만들 때 어떤 내용을 쓸지보다 먼저 결정해야 할 것은 파일의 소유자가 누구인지였다.
